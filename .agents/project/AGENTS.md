## §7 concrete instantiation

### Tools
- **Database**: use the Neon MCP (`run_sql`, `describe_table_schema`, `get_database_tables`) for read-only checks, instead of writing a Prisma script. Read `production-safety.md` first: the default database is production.
- **Schema**: read `backend/prisma/schema.prisma` and [wiki data model](../../wiki/architecture/data-model.md) instead of the generated client in `backend/src/prisma/generated/` (git-ignored, large).
- **Library behavior**: grep `node_modules/<package>` for the fact before changing how BlockNote, Socket.io, Nest or Prisma behaves. Do not guess from the API name.

### Files to skip
- `pnpm-lock.yaml` (≈500 KB), `frontend/src/routeTree.gen.ts` (generated by the TanStack Router plugin), `frontend/src/components/ui/` (shadcn copies), `.claude/skills/neon*` (vendored Neon skills, see `skills-lock.json`).

### Testing
- Commands and the gate are in `testing.md`. Short form: narrow Jest runs while working, `pnpm review` once at the end.
- No baseline run of `pnpm review` before starting a task.

### Running the app
- Backend: `pnpm --filter backend start:dev` (port 3000, routes under `/api`). It uses the production database.
- Frontend: `pnpm --filter frontend dev` (port 5173). It calls `VITE_API_URL`, or `http://localhost:3000` if unset.

### Background work
- Use `run_in_background` for long commands (dev servers, deploy). Never `sleep` in a loop to wait.
